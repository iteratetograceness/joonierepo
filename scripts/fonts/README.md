# Fonts

The site's only web font is Figtree (variable, `wght` 300–900, OFL with no Reserved Font Name). It is
self-hosted as two subsets generated by `subset_figtree.py`, which you run by hand. `next build` does
no font processing; it serves the committed output.

| File | Contents | Loaded |
| --- | --- | --- |
| `public/fonts/figtree-core.<hash>.woff2` | ASCII, Latin-1, ı Œ œ, combining macron/diaeresis, ‘ ’ “ ” – — … • | Preloaded on every page |
| `public/fonts/figtree-ext.<hash>.woff2` | The rest of Latin Extended-A (Figtree has 109 of its 128 characters), plus any other character the content uses | Only when a page contains one of them (`unicode-range`) |

Both files keep the full weight axis, kerning (`kern`), mark positioning, `ccmp`, `rvrn` (heavy-weight
dollar sign) and `tnum` (list markers). Hinting, glyph names, `STAT`, and every other OpenType feature
are dropped. CJK and other scripts Figtree does not cover keep rendering with system fonts.

The core holds everything Google's old "latin" file held that the site keeps, and the extended face is
declared first, so text shapes exactly as it did with `next/font/google`. The "Figtree Fallback" face
and `font-display: swap` are copied unchanged.

## Running it

```sh
python3 -m venv .venv-fonts
.venv-fonts/bin/pip install -r scripts/fonts/requirements.txt
.venv-fonts/bin/python scripts/fonts/subset_figtree.py
```

It rewrites `public/fonts/figtree-*.woff2`, `app/fonts/figtree.css` and `app/fonts/figtree.ts`, then
checks the output: the cmap matches the intended characters, no hinting survived, only the kept
features remain, vertical metrics are unchanged, and every character and pair of characters in each
file shapes to the same outlines and positions as the source font at weights 300–900. Reruns with
unchanged inputs produce byte-identical files. Commit everything it writes.

## When to rerun

- Content starts using a character outside ASCII, Latin-1 and Latin Extended-A (for example € ™ → or
  a Vietnamese letter). The script scans `app/`, `components/` and the root `.ts`/`.tsx` files and adds
  any such character Figtree has to the extended file. If it will often sit next to ASCII text, add it
  to `CORE_PUNCTUATION` so it keeps kerning with its neighbours.
- A style turns on an OpenType feature not in `FEATURES` (`font-feature-settings`,
  `font-variant-numeric: diagonal-fractions`, `ss01`...), or a page sets `lang` to a language with
  localized forms (tr, az, ca, nl, ro, ...), which needs `locl`.
- The site starts loading Figtree Italic instead of the synthesized italic.
- Figtree is upgraded in `source/`. The script warns when the source hash changes; re-check the
  pixel diffs and the "Figtree Fallback" metrics in `subset_figtree.py` before shipping.

## Optional flags (each changes rendering, so they are off)

- `--minimal-core`: core is ASCII + punctuation only (about 10.9 KB instead of 17.5 KB) and Latin-1
  moves to the extended file. Kerning between ASCII and accented Latin-1 letters ("Té", "Vá") is lost
  because they end up in different files.
- `--limit-wght`: cuts the axis to the 300–700 the site uses (about 1.2 KB off the core). Figtree only
  has masters at 300 and 900, so this re-encodes the outlines with rounding; glyphs move by fractions
  of a pixel on every page, and anything heavier than 700 would render differently.
